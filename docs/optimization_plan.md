# 优化规划：向优秀编译器看齐（中端 + 后端）

> 目标：把性能从"能过"提升到"优秀编译器"水准。中端与后端一起优化,**逐项实现、逐项本地对拍**。
> **基准以生成的汇编为准**：用 qemu 跑生成的 `.s`,量**动态指令数**(确定性,反映汇编真实做的工作),辅以 qemu 墙钟时间(反映调度/延迟)。每一项优化都要:**正确性(全量样例、两后端、-O0/-O1 全绿)+ 性能(基准有实测收益)**。
> 约束沿用一贯:保证通过全部样例、覆盖更多 SysY 情况、接口一致、代码风格一致、不牺牲优化力度去 debug、不用特殊判断去 debug。

---

## 0. 基准测试方法(先搭好,没有度量就没有优化)

### 0.1 指标
1. **动态指令数(主指标,确定性)**：qemu TCG 插件 `libinsn.so` 统计 guest 实际执行的指令条数。本机 qemu 6.2 已编译进插件支持(`-plugin` 可用),只需 build `contrib/plugins/libinsn.c`(需 `qemu-plugin.h`)。这是"以生成的汇编为准"的核心度量——直接反映汇编的效率,不受本机噪声影响。
2. **墙钟时间(辅指标,反映延迟/调度)**：qemu 用户态跑,取 N 次中位数。动态指令数**不会**体现指令调度、`stp/ldp`、延迟隐藏的收益(它们不减少指令数,只减少周期),这类优化用墙钟交叉验证。
3. **静态指令数(快速 sanity)**：`grep -cE '^\t[a-z]' out.s`,防止码体积回退。

> **⚠ 指标修正(B3 时发现)**:动态指令数隐含"顺序核 IPC≈1"的假设,对**延迟置换型**优化(用多条低延迟指令换 1 条高延迟指令,典型=常量除法魔数化)会**误判为回退**——魔数把 1 条 `sdiv/divw`(乱序核上 20~30+ 周期、阻塞除法器)换成 ~7 条单周期 ALU,指令数 +,但真实**周期** −。两台评测机(RISC-V=FPGA 上 BOOM 乱序核;ARM=跑完整 Ubuntu,几乎必是 Neoverse/A72 级乱序核)都是乱序核,魔数除法是真加速(A72 实测 4.6×,`llvm-mca`)。**结论**:指令数继续作主筛(覆盖 DCE/寻址折叠/LICM/CSE/强度削弱等"既减指令又减周期"的优化),但**延迟置换型优化改用 `llvm-mca` 对热点基本块估周期 / 乱序核推理**定夺,不被指令数误导。常量除法带 `-no-magic-div` 开关便于上板 A/B。

### 0.2 harness(`bench.sh`,待建)
对每个性能样例(riscv_performance 57 + riscv_finalperformance 60,以及 AArch64 用 qemu-aarch64 的同一批):
```
编译(-O1) → 汇编链接 → qemu -plugin libinsn.so 跑(带 .in)→ 记录动态指令数
```
聚合:各样例 `优化后/基线` 比值的**几何平均**,得到单一"提速比";同时输出每样例明细。两后端(RV / AArch64)各出一份。

### 0.3 每项优化的工作流(严格遵守)
```
1. 记录基线(当前 HEAD 的 bench 数)
2. 实现该优化(可开关:middle-end 走 pass 管线;backend 走 MachinePassManager,-O≥1 开)
3. 正确性:functional 100 + h_functional 40 + perf 输出对拍,RV 和 AArch64 各 -O0/-O1,必须全绿
   —— 若某后端不适用(纯目标相关),至少另一后端 + 该后端全绿
4. 性能:bench 对比基线,记录几何平均提速 + 有回退的样例
5. clang-IR A/B 判据仍是区分中端/后端 bug 的利器
6. 通过则提交(commit message 写清该优化 + bench 数)
```
关键纪律:**动态指令数是主,墙钟是辅**;调度类优化看墙钟,消冗余/强度削弱类看指令数。

## 1. 现状盘点
- 中端已有:mem2reg(promotion)、SCCP、GVN、ADCE、DSE、LICM、SCEV、强度削弱、循环全展开+部分展开、函数内联、尾递归消除、alias/memoryssa、trivial block merge、dead loop elim、canonicalization。**较完整,但深度和触发条件有提升空间。**
- 后端:图着色寄存器分配(IRC,含合并)、M4b 机器窥孔(立即数折叠、`mul`→移位[仅 2 的幂]、机器 DCE、分支折叠)。**缺:magic 除法、寻址模式折叠、指令调度、`stp/ldp`、常量复用、叶函数省帧。AArch64 机器 pass 一个都没有。**

## 2. 中端优化清单(目标无关,两后端同时受益——优先做通用大件)

| # | 优化 | 说明 | 预期收益 | 度量 | 工作量 |
|---|---|---|---|---|---|
| M1 | **常量除法/取模 → magic number** | `x / C`、`x % C`(C 编译期常量)→ 乘高位+移位(Hacker's Delight)。div/mod 延迟极高,crypto/hash/取模热点大赢。放中端则两后端都受益(也可后端做)。 | 高 | 指令数+墙钟 | 中 |
| M2 | **循环强度削弱 + 归纳变量优化** | SCEV 驱动:把循环内 `i*C`、`a[i]` 地址等换成加法递推的归纳变量(IV);消除冗余 IV;线性测试替换(用一个 IV 判循环退出)。matmul/数组遍历核心。 | 高 | 指令数 | 中高 |
| M3 | **LICM 深化 + memoryssa 提升** | 把循环不变的 load(经 memoryssa 证明不被写)、地址计算、纯运算全提出循环。检查现有 LICM 是否覆盖 load/GEP。 | 高 | 指令数 | 中 |
| M4 | **更激进的内联 + 内联后清理** | 小函数/单调用点无条件内联;内联后重跑 SCCP/GVN/DCE。`_and/_xor/_or` 这类小函数内联后能大幅简化(crypto)。 | 中高 | 指令数 | 中 |
| M5 | **指令组合/代数化简补全(canonicalization)** | `x*2→x+x`、`(a+C1)+C2→a+(C1+C2)`、`x&0`、`x|-1`、比较链化简、`a-a→0`、乘加合并(为后端 madd/msub 铺路)、位运算恒等。补全模式表。 | 中 | 指令数 | 中 |
| M6 | **循环展开启发式调优** | 按循环体大小 × 迭代次数决定展开因子;小 trip-count 全展开,大的部分展开 + 尾循环;避免码爆炸。现有 unroll 调参。 | 中 | 指令数+墙钟 | 低中 |
| M7 | **全局代码移动 / IR 层调度(GCM/GVN-PRE)** | 部分冗余消除(PRE):把只在部分路径算的值提到公共前驱;GCM 把计算沉到最少执行的位置。 | 中 | 指令数 | 中高 |
| M8 | **if-conversion(条件选择)** | 短的 if/else 无副作用分支 → select(后端出 `csel`/RV 无 select 用算术)。减少分支、利于后端。 | 中 | 墙钟 | 中 |
| M9 | **循环交换 / 分块(matmul 局部性)** | `i-j-k` → `i-k-j` 改善访存局部性;分块(tiling)提升 cache。matmul/spmv 大赢,但需 cache 模型判断收益。 | 高(特定) | 墙钟 | 高 |
| M10 | **尾复制 / 跳转穿线(jump threading)** | 消除跳到跳、把常量条件的分支直连。 | 低中 | 指令数 | 低中 |

## 3. 后端优化清单(码质量,直接决定 .s)

| # | 优化 | 说明 | 预期收益 | 度量 | 工作量 |
|---|---|---|---|---|---|
| B1 | **AArch64 机器 pass(A6)** | AArch64 目前零机器优化。移植 RV 窥孔框架 + 补 AArch64 专属:立即数折叠(`add #imm`/`cmp #imm`)、`mul`→`lsl`、机器 DCE、分支折叠。**先做,AArch64 唾手可得的收益最多。** | 高(AArch64) | 指令数 | 中 |
| B2 | **寻址模式折叠** | GEP 的 `base+idx<<k` 折进 `ldr/str [base, idx, lsl #k]`(AArch64)/ base+imm(两者)。数组代码无处不在,当前是朴素 `mul+add+ldr [x,#0]`。 | 高 | 指令数 | 中 |
| B3 | **magic 除法(若不在中端做)** | 后端窥孔把常量 `sdiv/remw` 换 magic。与 M1 二选一或互补(中端做覆盖面广,后端做更贴近目标)。 | 高 | 指令数 | 中 |
| B4 | **指令调度(list scheduler)** | 表调度重排,隐藏 load-use、乘/除、浮点延迟,提升 ILP。**两后端都没有。** 收益体现在墙钟(不减指令数)。需简单延迟模型。 | 中高 | 墙钟 | 高 |
| B5 | **`stp/ldp` 成对(AArch64)** | 相邻 `str/ldr` 合并成 `stp/ldp`(序言尾声 callee-saved、数组连续访问)。减指令+减周期。 | 中 | 指令数+墙钟 | 中 |
| B6 | **叶函数省帧 / 省 fp-lr** | 叶函数(无 call)且无 spill/alloca 时,不建栈帧、不存 fp/lr。大量小函数直接省 4-6 条。 | 中 | 指令数 | 低中 |
| B7 | **寄存器分配增强** | ① 重物化(rematerialization):溢出时对便宜值(常量、地址)重算而非 load;② 溢出代价按循环深度加权(别溢出热循环变量);③ 活跃区间拆分。 | 中高 | 指令数 | 中高 |
| B8 | **常量复用 / 机器 CSE** | 同一常量/全局地址(`adrp+add`)在块/函数内复用,别每次重算(现在 GEP 每次都 `adrp;add` 或 `li`)。 | 中 | 指令数 | 中 |
| B9 | **乘加合并** | `a+b*c → madd`、`a-b*c → msub`(AArch64 原生;RV 无,跳过)。中端 M5 铺路后后端识别。 | 中(AArch64) | 指令数 | 低中 |
| B10 | **块布局 + 循环对齐** | 按执行频率排块使热路径 fall-through、回边对齐;减跳转+利于取指。 | 低中 | 墙钟 | 中 |
| B11 | **post-RA 冗余 load/store 消除** | 分配后消除"存了又立刻读同一槽"、重复 load 同地址。 | 中 | 指令数 | 中 |

## 4. 优先级与里程碑(建议实现顺序)

**Tier 0 — 先搭基准(阻塞项)**
- **P0** build qemu `libinsn.so` 插件 + 写 `bench.sh`(RV/AArch64 两份,动态指令数几何平均 + 墙钟)。没有它后面都没法量化。

**Tier 1 — 高性价比,先做**
- **B1** AArch64 机器 pass(收益最集中,AArch64 现在裸奔)
- **B2** 寻址模式折叠(两后端,数组代码普惠)
- **M1/B3** magic 除法(定一处做)
- **B6** 叶函数省帧(简单、普惠)
- **M2** 循环强度削弱 + IV 优化(热循环核心)

**Tier 2 — 中等**
- **M3** LICM 深化、**M4** 激进内联+清理、**M5** 代数化简补全
- **B7** 寄存器分配增强(重物化 + 循环深度溢出代价)
- **B8** 常量/地址复用、**B5** stp/ldp、**M6** 展开调参

**Tier 3 — 大件/进阶(收益大但工作量大)**
- **B4** 指令调度、**M7** PRE/GCM、**M8** if-conversion、**M9** 循环交换/分块、**B10** 块布局
- (**天花板**)**向量化(NEON / RVV)**:潜在最大收益、工作量最大,竞赛期视精力决定是否上。

---

## 5. 两个后端的注意点
- 中端优化是目标无关的:实现一次,RV 和 AArch64 都要跑对拍(正确性)+ 各出 bench(性能)。用 clang 编中端 IR 的 A/B 判据继续区分中端 bug vs 后端 bug。
- 后端优化目标相关:RV 与 AArch64 各自实现(部分可共享,如寻址折叠的框架)。**趁此把复制的图着色分配器抽成共享核心 + `RegAllocHooks`**(去掉那份 800 行重复,B7 的增强只写一处)——这既是清理也是为 B7 铺路。
- AArch64 独有能力(`csel`/`madd`/`msub`/`stp/ldp`/带 extend 的寻址)是相对 RV 的额外码质量点,别浪费。
